## ① 本命：個人投資家のための自然言語投資LLM
（Natural-language investment LLM for retail investors）

**背景・問題**
- 個人投資家は「何を聞けばよいか」が分からないため、LLMに頼る。しかしLLMには次の問題がある。
  - 数値の捏造：どの資料にもない数値を答える。
  - 時点の誤り：古いデータや、質問した日付ではまだ公開されていないデータを使う。
  - 期限切れの知識：「MACDが0を上抜けたら買い」のように、ある時期には効いたが別の時期には効かなかったルールを、常に正しいかのように答える。
  - バイアス：質問者の前提に合わせる（迎合）。よくある意見を事実のように繰り返す。
- この問題設定は、トレーダーの先輩からの助言がもとになっている。

**提案**
- 自由な質問（テンプレートも用意）に答えるシステム。質問を6種類に分けて、それぞれ別の方法で答える。

| 種類 | 例 | 答え方 |
|---|---|---|
| 1 事実の検索 | 「トヨタの前期の売上は？」 | 数値は必ずDBから |
| 2 スクリーニング | 「日次ボラティリティ5%超、浮動株20%超の銘柄」 | クエリ化し、曖昧なら聞き返す |
| 3 定義・仕組み | 「金利が上がるとなぜ債券価格は下がる？」 | 出典つきの説明 |
| 4 関係・戦略 | 「ブレイクアウト投資は今も効く？」 | いつ、どんな条件で成り立ったかの根拠 |
| 5 意見・評価 | 「この株は割高？」 | 誰がいつ言ったか、両方の立場 |
| 6 個人の判断 | 「100万円あるけど、どうすればいい？」 | 1〜5の質問に分解する。個別の助言はしない |

- 知識を3種類に分けて、保存の仕方も見せ方も変える。
  - **絶対的な知識**：定義、公開日つきの数値。値・出典・公開日時と一緒に保存し、事実として示す。
  - **条件つきの知識**：「出来高を伴うブレイクアウトは続きやすい」など。成り立った期間と市場の条件、未来情報を使わない検証の結果、最終確認日と一緒に保存する。「高ボラティリティ期には成り立ったが、直近6か月は成り立っていない」のように示し、「常に正しい」とは言わない。
  - **意見**：「アナリストAはこの株を割高と見ている」など。誰が・いつ・どちらの立場かと反対意見を保存し、意見として明示する。
- 構成（先輩の挙げた4要素に対応）：①金融DB、②API／MCPによるツール接続、③データパイプライン（価格・提出書類・文書・ニュースに日付と種類を付ける）、④LLMとDBの接続。さらに、根拠のない主張を削除して「分からない」と答える検証器を加える。
- 目標は、ハルシネーションとバイアスを「なくす」ことではなく、「減らし、見える化し、測る」こと。

**研究課題（案）**
- RQ1：知識を絶対・条件つき・意見にどの程度正しく分類できるか。
- RQ2：LLM単体や通常のRAGと比べて、根拠のない主張と数値の誤りがどれだけ減るか。
- RQ3：質問者の前提（「なぜ買いか」と「なぜ売りか」）による答えのぶれが、どれだけ減るか。

**評価**
- 6種類にまたがる200〜300問のベンチマーク。各問に、問い合わせ日付・正解・正解ラベルを人手で付ける。
- 比較対象：LLM単体、通常のRAG。
- 範囲：まず1市場（米国大型株、SEC EDGAR + FRED、英語）。

**スパイク1（`01_llm_claims/`、実データ：Apple 2025年度 10-K、SEC EDGAR）**
- 時点クエリ：XBRLの売上高を見ると、同じ決算期の値が2〜3回、別々の書類で報告されていた。Appleの場合、値は変わっていなかった。
- 2025年度の売上（4,161.61億ドル）は 2025-10-31 に初めて公開された。決算期末の 2025-09-27 時点で問い合わせると「まだ不明」と返す。この仕組みで未来情報の混入を防ぐ。
- 文の分類：MD&A の75文を、キーワードによるルールベースの基準手法と参照ラベルで比べた。参照ラベルはLLM（Claude）が付けたもので、人手で検証した正解ではない。
  - 一致率は **31%** にとどまった。分類にはLLMが必要。
  - 主な失敗1：数値のない事実の文を「その他」にした（23文）。例「欧州の売上は2025年に増加した」。
  - 主な失敗2：「will」を一律に予測と判定した。実際には、会計基準の適用時期のように予定された事実である（5文中5文を誤判定）。
  - 1文に2種類の主張が入っている文が **11%**（8文）あった。1文に1ラベルでは情報が失われるので、主張単位に分割する必要がある。
  - 「〜は主に…のため増加した」型の文が13文あった。数値は事実だが、原因の説明は経営陣の解釈である。

**スパイク2（`04_lookahead/`）：条件つきの知識を「カンニングなし」で検証するために**
- ある時点より後の価格を別の未来に差し替えて、もう一度実行する。それ以前の判断が変わったら、その戦略は未来を見ている。
- テスト用データは純粋なランダムウォーク（本当のシャープレシオは0）。

| 戦略 | シャープ | 単純なテスト | 厳密なテスト |
|---|---|---|---|
| MAクロス（正しい） | 0.07 | 合格 | 合格 |
| MAクロス、shift忘れ（バグ） | 1.01 | **見逃し** | 検出 |
| 全期間平均でzスコア（バグ） | 0.27 | 検出 | 検出 |
| 中心化移動平均（バグ） | 3.87 | 検出 | 検出 |
| 拡大窓zスコア（正しい） | −0.07 | 合格 | 合格 |

- 最もよくあるバグ（shift忘れ）は単純なテストでは見逃され、厳密なテストで検出できた（バグ3つ中3つ）。

**リスク**
- 条件つきの知識が最も難しい。まずよく知られたルールや関係を20〜30個選び、それぞれを時期ごとに検証する。
- 似たアシスタントはすでにある。違いは知識の状態ラベルと、誤りの減少を測ること。先に先行研究の調査が必要。
- データの制約：まず1市場。浮動株比率など、無料で取れない項目もあり得る。
- 個別の投資助言はしない。利用者自身の判断のための情報を出す（日本では法律上の線引きでもある）。

## ② シミュレーション：市場は「循環」するか（人工市場）

**問い**
- 「みんなが同じテクニカル指標を使うと効かなくなり、使われなくなるとまた効くようになる」というトレーダーの経験則は本当か。
- 3つのつながりに分けて検証する：(1) 混雑すると効かなくなるか、(2) 使う人が減るとまた効くか、(3) 混雑そのものが波（循環）を作っているか。

**スパイク（`02_market_abm/`）**
- 投資家1000人のエージェントモデル。各自、指標に従うか休むかを、指標の最近の成績に応じて切り替える（Brock–Hommes 型のロジット選択）。大口投資家は入れず、混雑の効果は価格インパクトだけにした。
- 価格インパクトの強さを4段階、4シード、トレンドの種類2通り（切り替わる／一定）で比較した。対照実験は同じ乱数で価格インパクトなし。

次の20ステップの指標の成績（bp/step、4シード平均）：

| 価格インパクト | 使う人が少ない20%の期間 | 使う人が多い20%の期間 | 使う人の割合（平均） | 対照との相関 |
|---|---|---|---|---|
| なし（対照） | +0.4 | +1.1 | 0.55 | 1.00 |
| 弱 | −0.2 | −2.2 | 0.48 | 0.97 |
| 中 | −0.7 | −5.1 | 0.43 | 0.93 |
| 強 | −1.1 | −10.4 | 0.37 | 0.87 |

- 結果1：(1) 混雑すると効かなくなる → 価格インパクトがある場合のみ成り立つ。インパクトが強いほど悪化する。
- 結果2：(2) 使う人が減るとまた効く → ほぼ成り立つ。使う人が少ない期間の成績は、インパクトなしの水準に近い。
- 結果3：(3) しかし循環そのものは混雑が作っていない。使う人の割合の波は、インパクトありとなしでほぼ同じ（相関 0.87〜0.97）。トレンドが一定で指標の本当の優位性が変わらない場合でも同じだった。波は「最近の運の良し悪し」を追いかけることから生まれている。混雑は人数を小さく保つブレーキであり、周期を作る時計ではない。

**位置づけと今後**
- Brock–Hommes (1998)、Lux–Marchesi (1999)、日本の人工市場研究（和泉研、PAMS、SIG-FIN）に対して、新しさを明確にする必要がある。
- 次は、別の切り替えルール（他人の模倣など）で循環が起きるか試す。実データで「混雑の代理指標」と指標の成績の関係を確認する。

## 実行方法

Python 3.10 以上。

```bash
pip install -r requirements.txt
```

**01_llm_claims**（標準ライブラリのみ）

```bash
cd 01_llm_claims
python spike_llm.py fixture     # オフライン確認（合成データ）
python compare_labels.py        # ルール基準手法と参照ラベルの比較（31%）
```

`asof` と `mdna` は SEC EDGAR にアクセスします。SEC は User-Agent に名前と連絡先を求めているため、先に環境変数を設定してください。

```bash
export SEC_USER_AGENT="Your Name your.email@example.com"
python spike_llm.py asof        # Apple の時点クエリ
python spike_llm.py mdna        # 最新 10-K の MD&A を取得して文を分類
```

**04_lookahead**

```bash
cd 04_lookahead
python lookahead_detector.py
```

**02_market_abm**

```bash
cd 02_market_abm
python market_cycle.py --plot result.png   # 1シード、インパクトあり／なし（約10秒）
python sweep.py                            # 4段階 × 4シード × 2通り（数分）
```
